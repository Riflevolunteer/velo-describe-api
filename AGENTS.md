# Repository housekeeping

For repository work, read the relevant item in `TODO.md` and follow
[TODO and scratchpad housekeeping](.agents/skills/audit-data-quality/references/todo-housekeeping.md).
Update the worklist as decisions are verified and complete housekeeping before
reporting the task finished. This applies to API/client work as well as data work.
TODO.md holds only actionable next steps: no counts or snapshots, no completed
work, no decisions or hunt logs (see the table in the housekeeping file for where
each goes). Record lasting results in the relevant existing notes and remove
completed tasks. Git history retains committed task history.

Housekeeping is part of the task, without a user reminder or separate cleanup
request. Apply it at each verified result, including between items in a batch:

- Before adding an item, search for the existing task and update it in place.
- When an action is applied and validated, record lasting evidence in the
  existing notes and remove that action immediately. For partial completion,
  replace the old item with only the remaining action; do not append a progress
  narrative beneath it.
- Add a follow-up only for a concrete unresolved action. An intentional unlinked
  value, reviewed non-duplicate or unsuccessful search is a decision/evidence
  record, not automatically another task.
- Before reporting completion, review the task's TODO diff and search the rest
  of TODO for the affected names/IDs. Remove completed or duplicate entries and
  reconcile stale claims. Verify notes, links and scratch cleanup in the same
  pass. Do not report the task finished while this check remains outstanding.

Clean up temporary files created for the task as they become unnecessary. Preserve
what is needed for pending review, validation or resuming unfinished work; follow
the linked rules before deleting files.
